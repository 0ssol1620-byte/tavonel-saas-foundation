## 1. The truth contract

The rules below are the reason this landing can be read as evidence rather than as marketing.
Each one names where it is enforced, because a rule with no guard is a comment.

**Every figure is measured, not typed.** No string in `lib/landing-v2-copy.ts` may contain a
digit — `lib/landing-v2-copy.test.ts` asserts it — so a count can only reach the page through a
module that read it out of the compiled public World. Every rendered figure sits inside an
element marked `data-derived="1"`, and `e2e/landing-v2.spec.ts` walks the live DOM of both pages
stripping those elements and fails on any digit left behind.

**Every image is a real page.** No illustration, no synthetic document, no stock. Every pixel
under `public/landing/v2/` is a resize or a crop of a committed raster under
`public/explore-sample/pages/`, which is itself a render of a committed source PDF.
`scripts/build-landing-v2-assets.mjs` re-hashes each input against `pages.manifest.json` before
reading a pixel and stops rather than re-encoding a drifted raster.

**No claim the deployment cannot make.** The forbidden-phrase list is blueprint §20.2 plus
`lib/brand-copy.test.ts`'s `BARRED`, `OVERCLAIMS` and `RETIRED_NAMES`; `LANDING_V2_FORBIDDEN` in
`lib/landing-v2-copy.test.ts` sweeps the copy deck, and `lib/prohibited-phrases.test.ts` sweeps
every non-test file under `app/`, `components/` and `lib/`.

**Exactly three actions exist.** `EXPLORE_CTA` ("Explore a Compiled World" → `/explore`) and the
two access actions, `ACCESS_CTA` ("Request access" → `/contact`) and `SELF_SERVE_CTA` ("Start
with your files" → `/login`). Which access action applies is `isLiveCommerce()` and nothing on
this page decides it. Every test that touches an action asserts *one of the two* — the CI Product
QA job runs with `COMMERCIAL_MODE=live` and `TAVONEL_BILLING_LAUNCH_APPROVED=true` and still
resolves to the access posture, because `lib/commercial-state.ts` also requires
`activationPolicy.customerData.enabled`, which is `false` in this deployment.

**Where the deployment gate is stated, it is stated verbatim.**
`activationPolicy.customerData.reason` is rendered as-is in Scene 07 and Scene 09 — never
paraphrased, and the element disappears when the gate opens rather than being reworded.

**No customer logo, quote, certification, SLA or uptime figure** appears anywhere on the page.

### The data modules

Server-only, every one of them: they reach the collection compiler through
`lib/explore-sample.ts`, and importing any of them from a client component would ship the
compiler to a browser.

| Module | What it builds |
|---|---|
| `lib/landing-v2-proof.ts` | `buildProofTabs()` (Scene 02), `buildEvidenceRecord()` (Scene 04), `buildRecompileView()` (Scene 05), and `landingV2StateWord()` — the World's own word for an object's state |
| `lib/landing-v2-sources.ts` | Scene 03's source stack and object vocabulary (memoized in-module) |
| `lib/landing-v2-evidence.ts` | Scene 04's field labels and the two region-unit nouns |
| `lib/landing-v2-recompile.ts` | Scene 05's action table and the qualifier that says what the counts compare |
| `lib/landing-v2-assets.ts` | the read side of `public/landing/v2/manifest.json`, addressed by source digest + page (+ bbox) rather than by a concatenated path |
| `lib/landing-v2-copy.ts` | every sentence, in both languages, carrying no digit |
| `lib/landing-v2-hero-copy.ts` | the §11.3 film note, /explore's short Entity caveat, and the Korean label and caption for each of the four locked cuts |

`lib/landing-experiments.ts` sits beside them and is the one module here that is not server-only:
it is read on the server (both entry pages are `force-dynamic`, so the arm cookie is read there)
and the resolved arm travels down as a plain string. See §6.

`landing-page.tsx` memoizes the three builders at module scope. The World behind them is frozen
at build time and every builder is pure over it, so a module-level memo is the whole of what is
needed — there is nothing that can change it while the process lives.

### The digests

Scene 04's evidence record is Apple's 2025 Form 10-K, page 4, the "Company Background" region at
the per-mille box `[30, 291, 971, 380]`, chosen by `chooseExploreEntryProof()`; its source digest
is `sha256:108590052c3ba5400c63660d787fe7ed4e43868292946d7a7facebe9ab7d1aab`. The page prints that
digest truncated, with the full value in the element's `title` and in the copied citation. (Until
2026-09-20 the hero showed the same record, and `lib/landing-v2-hero.test.ts` pinned the digest;
both left with the compiler-demo hero.)

`public/landing/v2/manifest.json` records, for each of its eight entries, the sha256 of the
source raster and the sha256 and byte length of every file written from it.
`lib/landing-v2-assets.test.ts` re-checks all of that against the files on disk, and fails when a
region the proof scenes resolve to has no derivative.

The semantic table is site-wide, not landing-only. A colour means one thing in the app and the
same thing here (§5.2):

| Token | Meaning | Value |
|---|---|---|
| `--source` | source · document · location | `#7da7ff` |
| `--verified` | verified · active · safe | `#7be0be` |
| `--relation` | relation · compiled structure | `#a996ff` |
| `--changed` | source update · changed dependency | `#f2a65a` |
| `--unresolved` | unresolved · held for review | `#f07d73` |

`--unresolved` moved from the blue family to coral in this round, so that blue means *location*
and only location on both surfaces. Each accent has an `-ink` variant for use as text on the
paper ground (`--source-ink`, `--relation-ink`, `--unresolved-ink`, `--verified-ink`,
`--changed-ink`), because the dark-ground shades do not clear 4.5:1 on paper.

Colour is never the only carrier of state: every state dot on this page has a word beside it.

### Type and grid

Three faces, all through `next/font/google` in `app/layout.tsx` — nothing contacts a font host at

Landing type scale (`app/landing-v2.css`), which is **below** the blueprint's at every

| Token | < 768 | base | ≥ 1200 |
|---|---|---|---|
| `--lv2-display` | `clamp(32px, 9vw, 40px)` | `clamp(46px, 4.6vw, 52px)` | `clamp(44px, 3.9vw, 56px)` |

| `--lv2-meta` | `12px` | `13px` | — |

Every step in that row is a MEASUREMENT (P3 QA round 1 and the fix round after it), read off the
rendered page in Chromium **and** WebKit at eight widths on both locales, not an arithmetic from an
assumed em advance. What the measurement fixes in place: in the 600px hero text track the English
headline sets in two lines up to 58px and three from 60px; at 360 it sets in three lines at 32px in
both engines and in four at 34px in WebKit. An earlier scale raised this to
`clamp(56px, 5vw, 72px)` / `clamp(40px, 10vw, 46px)` and widened the hero's text track to 752px to
hold it, which put the English H1 on four lines on a phone and inverted §32's 42:58 text:visual
ratio to 58:42.

measure: `clamp(24px, 7vw, 30px)` below 768, `clamp(34px, 4.1vw, 42px)` to 1199 and
`clamp(38px, 3.06vw, 44px)` from 1200, all measured the same way. The phone step is taken from
WebKit, which sets this headline about 4% wider than Chromium and crosses the three-line cap first.

Grid: `--lv2-wrap: min(1296px, calc(100% - 2 * var(--lv2-gutter)))` with `--lv2-gutter` stepping
20 → 32 (768) → 48 (1200) → 72 (1440). `app/chrome-v2.css` takes the identical measure as header
padding, so the wordmark sits on the same left edge as the landing content. Three layout kinds
only: Full Bleed Scene, Editorial Split (`.lv2-split`, 4 col text + 8 col visual) and Evidence
Grid. No bento, no card inside a card.

**The 12px floor is hard.** `scripts/check-type-floor.mjs` runs first in `pnpm check` and scans
every stylesheet; mono metadata is 12–13px and never 11px, which is where the blueprint's

## 5. Motion, and what happens when it is switched off

Movement means a state change, never decoration (§23). Timing and easing come from the five
motion tokens above and from nowhere else. No scroll hijack, no parallax, no particles, no
mouse-following anything, no card-hover scale, no rotating 3D, no WebGL, no canvas.

The hero storyboard is a 16-second CSS timeline — seven beats of two seconds and a two-second
hold — on a shared clock, with each element's window expressed as a percentage of it. There are
no delays, no stagger arithmetic and no scheduler, because the first frame has to be the
server's and the loop has to run before `hero-compiler-demo.tsx` has hydrated.

### The hero has three states, and all three show the whole composition

Recomposed 2026-09-19 (F1–F5). There is no rotating slot: the six objects — the region strip, the
page thumbnail with its box, the compiled claim, the bound objects, the arrivals and the
comparison counts — each hold a grid cell of their own, and the sequence changes emphasis rather
than presence.

| State | What is on screen |
|---|---|
| **Resting** (t=0, and any object before its beat) | Every object, painted, at `--lv2-rest` = 0.85 opacity |
| **Emphasis** (the seven beats) | Each object rises to 1 at the start of its beat and stays there: strip and thumbnail (0–2s), the box with one pulse and the Evidence Line drawn to it (2–4s), the claim with its own line (4–6s), the objects (6–8s), the state word with one dot swell and the coordinate (8–10s), the arrivals (10–12s), the counts (12–14s) |
| **Hold** (14–16s) | The whole hero at full strength, which is what a screenshot at any instant after 14s catches |

0.85 is a contrast measurement, not a taste: the quietest text in the demo is `--text-lo` on
`--ink-950`, 6.48:1 at full strength, and an ancestor's opacity multiplies into that where no
automated sweep can see it. It passes 4.5:1 down to about 0.80 (0.78 measures 4.30:1, 0.55
measures 2.66:1), so 0.85 is the lowest value that keeps every de-emphasised sentence readable
for the seconds before its beat — above F2's floor of 0.55 and visibly a step below 1.

**Every animation runs backwards from its finished state.** An element's base CSS is what it
looks like when the beat is over; the keyframes take it back to `--lv2-rest` and return it. That
is what makes reduced motion correct rather than approximately correct: `app/landing-v2.css`
collapses every animation to 1ms and one iteration, and a finished CSS animation with the default
`animation-fill-mode` reverts the element to its base style. Since no element's base is hidden any
more, that collapse lands exactly on the hold state.

**Reduced motion** is therefore the hold state, statically, with the explicit play control still
present and defaulting to paused — and the narration is the FINAL caption alone. Two earlier
rounds argued that both ways, and both were right about a hero whose objects took turns: when
four panels rotate, the transcript is the only place the whole story exists (§26 names exactly
that substitution). That hero is gone, so six more sentences would describe a picture the reader
is already looking at, at a cost of 151px of hero.

**Below 768 there is no sequence at all.** The phone gets the static complete composition: all six
objects at full strength on the first frame, the strip re-flowed as two readable halves, no
rotation, no narration row and no play/pause control — a control that cannot start anything is a
44px target that lies. The whole of that decision is one `@media (min-width: 768px)` around the
animation bindings, and `hero-compiler-demo.tsx` reads the same width before it creates the
`IntersectionObserver`, so a phone pays for no scroll callback either.

JavaScript in the hero does four things and no more: the 44px play/pause control, the
reduced-motion default, an `IntersectionObserver` that stops the loop when the hero is off
screen (≥768 only), and a fallback for the §4.1 signature interaction on engines without
`:has()`. The signature itself is CSS first, and the fallback writes an attribute straight onto
the node rather than going through React state — a hover that re-renders the hero is an INP cost
for a decoration.

## 6. Analytics, and the experiment switches

### The privacy contract comes first

`lib/funnel-events.ts` carries an enumerated property allowlist, `FUNNEL_DETAIL_KEYS`, and it is
the enforced half of the promise: the type rejects an unlisted key at the call site and
`trackFunnel` drops one at run time rather than trusting that every future caller compiled
against the file. No landing event carries an id, a filename, a question, a passage, a heading or
an href. What travels is a tab's ordinal position, which of three scenes a source was opened
from, the experiment arm, and nothing else. `lib/funnel-events.test.ts` pins the key list and
requires every `FunnelEvent` member to have a real caller in `app/` or `components/`.

Scene 04's clipboard button deliberately fires nothing. An event beside a Copy citation control
would be the one event on this page that could carry a passage of a document.

### One listener, not fifteen handlers

`components/landing-v2/landing-analytics.tsx` is mounted once inside the landing's `<main>` and
listens there. Eight of the nine scenes are server components that ship no JavaScript, and an
`onClick` on the links that matter would turn four of them into client components to fire an
event each. So the scenes expose a `data-analytics` attribute where the control is not a link and
a real `href` where it is, and the mapping from those to event names lives in one readable file.

It is scoped to `main` and not to the document, so a click on the header's Pricing link is not
counted as a landing conversion — `pricing_open` means the same thing on every page.

| Event | Fired by |
|---|---|
| `hero_primary_click`, `hero_secondary_click` | the hero's two controls, by position (the filled button, the text link) — which is what a CTA-order test has to be able to count |
| `hero_explore_clicked`, `hero_start_clicked` | the same two clicks, by destination. Kept rather than retired: they are the funnel's oldest landing columns |
| `cta_clicked { cta, scene }` | the action rows, from `hero-actions.tsx` |
| `hero_demo_interact` | the play/pause control and the two signature objects, on pointer *and* on keyboard focus, once per page session |
| `proof_claim_switch { cta }` | Scene 02's tablist, carrying the tab's ordinal position |
| `source_open { from }` | every "Open source" / "Open original" / hero claim link; `from` is one of three scene words |
| `integration_open`, `trust_open`, `pricing_open` | matched on the destination pathname rather than tagged per link, so a scene that adds a second link to the same place stays counted |
| `scroll_scene_25/50/75/100` | scene depth, not pixels: `index / (count - 1)` over the nine landmarks, so the quartiles land on scenes 3, 5 and 7 at any page height. Once each |
| `request_access_start`, `request_access_complete` | `components/contact-form.tsx` — first focus of the form, and a qualified submit beside `generate_lead` |
| `world_explore_60s` | `components/explore/explore-stage.tsx`, a dwell timer counted only while the tab is visible |

`world_explore_start` is deliberately absent: D7 says it is the existing `explore_entered`, and a
second name for one hop is two columns somebody adds together by hand forever.

### The experiment switches

`lib/landing-experiments.ts` (D8, §31). Off is the default, and it is the absolute kind of off:
with `NEXT_PUBLIC_LANDING_EXPERIMENT` unset — which is every deployment today —
`landingVariantState()` returns one frozen object, no cookie is ever written, and no `variant`
property reaches any event. Nothing on the entry pages behaves differently because the module
exists.

- One experiment at a time. The variable names exactly one test (`headline` or `cta_order`), so
  two tests can never overlap on a page view and a `variant` column is never ambiguous about
  which test it belongs to.
- `?lp=a|b|c` overrides the *arm*, not the switch. With no test active it does nothing at all — a
  query parameter that could change what the public landing says would make "off by default"
  something a URL can turn on.
- The cookie `tavonel.lp-variant` holds one character for thirty days, `SameSite=Lax`,
  first-party, written only while a test is active. It carries no identifier and nothing derived
  from the reader: it is the arm they were shown, kept so the second page view is not a different
  page. That makes it functional rather than analytical, which is why it sits outside the Google
  Analytics consent gate while the *measurement* of the arm stays inside it.
- A stale arm is safe. `LANDING_EXPERIMENT_ARMS` records that Test 01 has three arms and Test 02
  has two, so a reader holding "c" who arrives during the CTA test is shown the control rather
  than a third rendering nobody designed.

Test 03 (world-graph hero) and Test 04 (full dark) are backlog with a reason rather than unbuilt
by omission: 03-B needs a canvas hero the phone rule forbids and pushes the §37 graph-database
perception, and 04-A contradicts the obsidian/paper alternation the whole design rests on.

## 8. Direction, not shipped

Three things this page describes as a contract and never as a live capability. Each one is a row
in `lib/claim-state.ts`, and the wording on the page is checked against it.

1. **Selective (incremental) recompilation.** The five sample snapshots are complete compiles and
   `exploreChangeStory.equivalence.state` is `not_yet`. Scene 05 says which objects the arriving

   live selective rebuild, and it carries no equivalence badge.
2. **Own-file intake.** `activationPolicy.customerData.enabled` is `false`. Scenes 07 and 09
   state the gate verbatim.
3. **"What changed?" as an answerable question.** The Ask path in this deployment is a lexical
   retriever over the compiled World; it returns the source text of the regions it scored, not a
   composed answer. Scene 02 shows exactly that — the passage and its page. The hero used to
   repeat one of `EXPLORE_SAMPLE_QUESTIONS` with its real first citation in a Use beat; F2

## 9. Regenerating the derivatives and the rasters

Two steps, in this order, and both are regeneration tools rather than build steps — their outputs
are committed.

```bash
# 1. Page rasters from the committed source PDFs (only when a source or the render profile moves)
node scripts/render-source-pages.mjs
#    -> public/explore-sample/pages/*.webp + pages.manifest.json

# 2. Landing derivatives: resized pages and region crops, cut from those rasters
node scripts/build-landing-v2-assets.mjs
#    -> public/landing/v2/*.{webp,avif} + manifest.json
```

Step 2 is deterministic — sorted keys, no timestamps, fixed encoder settings (WebP q80/e6, AVIF
q55/e4) — so re-running it over unchanged inputs rewrites byte-identical files. A diff under
`public/landing/v2/` therefore means an input or a setting moved, and that is the only honest
reading of one. It fails closed if a source raster no longer hashes to its `pages.manifest.json`
entry.

`sharp` is not a dependency of this package. The script resolves it from the shared pnpm store by
absolute path; `pnpm install` must never be run in a lane worktree, because `node_modules` is a
junction and an install purges the shared tree.

Which widths exist is a literal list in the script, because the selection lives in TypeScript.
It cannot drift silently: `lib/landing-v2-assets.test.ts` fails when a region
`lib/landing-v2-proof.ts` resolves to has no derivative.
